## 二、关键实现

### 1. submit 缓存修复

旧缓存键：

```text
file_name|job_type|pdf_slice
```

新缓存键：

```text
file_name|job_type|pdf_slice|folder:<folder_id>
```

这样同一 PDF、同一页码范围，在个人目录和共享文件夹中会生成不同缓存，避免 silently 返回错误 `folder_id`。

### 2. 备注接口

接入接口：

```text
POST /api/v2/extractor/task/remarks
body: {"task_id": <int>, "remarks": <string>}
```

命令：

```powershell
patsight-cli submit --pdf-path demo.pdf --shared-folder-id 27463 --remark "Priority review"
patsight-cli patent remark set --task-id 2069693492657004544 --remark "Priority review"
patsight-cli patent remark set --task-id 2069693492657004544
```

说明：

- 备注最长 139 字符，与 Swagger 一致。
- 空备注用于清除现有备注。
- `submit --remark` 的备注失败会返回 `ClientError`，避免自动化把部分失败误判为成功。

### 3. 专利列表客户端筛选

命令：

```powershell
patsight-cli patent list --remark "Priority" --fetch-all
patsight-cli patent list --creator-email "owner@example.com" --fetch-all
patsight-cli patent list --unfiled --fetch-all
patsight-cli patent list --multi-folder --fetch-all
```

说明：

- 这些筛选不是服务端 query 参数，而是基于新版 `GET /tasks` 响应字段做本地过滤。
- 大数据量场景必须显式使用 `--fetch-all`，否则命令直接报错，避免只过滤当前页造成误判。

### 4. 本地 zip 批量导出

命令：

```powershell
patsight-cli patent export --zip --folder-id 27463 --fetch-all -o phase2_export.zip
```

zip 内容：

| 文件 | 内容 |
|---|---|
| `manifest.json` | 导出任务列表、成功/跳过计数、warnings、每条 task 元数据 |
| `metadata.json` | 专利元数据数组 |
| `exports/*` | 已完成 task 的导出文件 |

处理策略：

- 仅导出 `done/completed/success/finished` 任务。
- 非完成任务写入 manifest 并计入 `skipped_count`。
- editors 为 best-effort；接口不可用时写 warning，不阻断 zip。

## 七、风险说明

1. `patent export --zip` 是 CLI 本地打包能力，不代表后端已有服务端批量导出。
2. 客户端筛选依赖新版 `GET /tasks` 返回字段；如果测试环境列表接口未返回对应字段，筛选结果可能为空。
3. editors 不可用时 zip 仍会生成，但 `metadata.editors` 为 `null` 并记录 warning。
4. 批量导出可能触发多个单 task 导出请求，应控制筛选范围。
